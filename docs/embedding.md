# Эмбеддинги и гибридный поиск

Векторный поиск нужен для синонимии, которую не ловит FTS (например, запрос
«проверка строки по регулярному выражению» → метод `СтрПодобна`). Требует
сервиса эмбеддингов: локального OpenAI-совместимого (LM Studio, Ollama) или
облачного Hugging Face (вариант C).

Модель эмбеддинга **обязана совпадать с моделью индекса** (векторное пространство
должно быть одно). Готовый индекс (тег `ready-to-run-db`) собран моделью
**`bge-m3`** (1024 dims). Совместимость проверена: локальные варианты (LM Studio
FP16, OpenVINO) и облачная `BAAI/bge-m3` дают косинус ≈ 1.0 (0.99999).

> Ранее для облачного эмбеддинга использовалась `unsloth/Qwen3-Embedding-0.6B`
> (совместима с локальной `qwen3-embedding-0.6b`, косинус ≈ 0.9995). Модель снята
> с HF Inference (HTTP 410, deprecated) — перешли на `bge-m3`. Индексы, собранные
> на qwen3, работают только с локальным qwen3-эмбеддером; пересоберите индекс на
> `bge-m3`, чтобы использовать облачный вариант C.

## Вариант A — LM Studio

Загрузите модель **`text-embedding-bge-m3`** (1024 dims) и пропишите
`[embedder.index]`/`[embedder.query]` с `base_url = "http://localhost:1234/v1"`:

```toml
[embedder.index]
provider = "openai"                       # LM Studio — OpenAI-совместимый API
model = "text-embedding-bge-m3"
base_url = "http://localhost:1234/v1"
dims = 1024
```

## Вариант B — Ollama одной командой

Windows:

```powershell
.\scripts\setup-ollama.ps1              # установит Ollama, поднимет serve,
                                        # скачает bge-m3 (1024 dims) и покажет конфиг
```

Linux/macOS:

```bash
bash scripts/setup-ollama.sh            # то же самое (curl + официальный скрипт установки)
```

Скрипт выведет готовую секцию `[embedder.index]`/`[embedder.query]` для
`v8help.toml` (или значения для MCP-тула `config_set`). После этого:

```bash
v8help build          # пересобрать индекс с векторами (несколько минут)
```

и в `v8help.toml` переключите `[search] backend = "hybrid"` (либо
`config_set` → `{"search.backend": "hybrid"}`).

## Вариант C — Hugging Face Inference (облако, без своего сервера)

1. Зарегистрируйтесь на [huggingface.co](https://huggingface.co) и создайте токен:
   Settings → Access Tokens (права «Read» достаточно).
2. Вставьте токен в `api_key` секции `[embedder.query]` (для работы с готовым
   индексом этого достаточно; для полной индексации через облако — продублируйте
   в `[embedder.index]`, но индекс дешевле собрать локально вариантом A/B):

```toml
[embedder.query]
provider = "hf"                          # native HF pipeline, не OpenAI-формат
model = "BAAI/bge-m3"                    # та же модель, что построила индекс
base_url = "https://router.huggingface.co/hf-inference/models"
api_key = "<HF_TOKEN>"
dims = 1024
```

3. Готово: поиск (гибрид/векторы) работает по готовому индексу, локальный
   сервер эмбеддинга не нужен. `provider = "hf"` обязателен: роутер HF не отдаёт
   OpenAI-формат (`/v1/embeddings`) для `bge-m3`, нужен native pipeline.

## Зачем разделять `embedder.index` и `embedder.query`

Обе секции описывают **одну и ту же модель**: эмбеддинги запроса и индекса должны
лежать в одном векторном пространстве, иначе косинусная близость бессмысленна.
Разделение нужно по жизненному циклу:

- `embedder.index` — модель для сборки индекса (разовая фоновая операция, долго);
- `embedder.query` — модель для эмбеддинга текста запроса при каждом поиске
  (реальное время). Если не задана — берётся `embedder.index`.

Практический сценарий — **готовый индекс + облачная модель**: скачали БД с
векторами (см. [«Готовые индексы»](configuration.md#готовые-индексы-без-установленной-платформы)) — эмбеддинги уже посчитаны, собственный
сервер эмбеддинга для индексации не нужен. Тогда в `embedder.query` указывается
**та же модель** (`bge-m3`), но доступная через недорогой облачный API (вариант C
выше, `provider = "hf"`) — вместо того чтобы поднимать локальный сервер на целевой
машине. `provider` работает в обеих секциях: если лимиты/тариф позволяют,
`[embedder.index]` тоже можно указать `provider = "hf"` и строить индекс целиком
через облако.

## Провайдеры (`provider`)

- `openai` (по умолчанию) — OpenAI-совместимый `/v1/embeddings`: LM Studio,
  Ollama, любые прокси.
- `hf` — native Hugging Face pipeline (`{base_url}/{model}/pipeline/
  feature-extraction`). Требуется, если роутер HF не отдаёт OpenAI-формат для
  нужной модели (так для `bge-m3`).
